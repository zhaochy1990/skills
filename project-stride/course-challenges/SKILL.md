# 马拉松赛道难点查证

输入：一个马拉松比赛名（可带年份、可指定组别），或已到手的一条路线串。
输出：**按组别**的难点清单，可直接映射到 `race_calendar_item.content.course_challenges`（条目）与 `total_ascent_m`（总爬升）。

难点用类型前缀标注：**【坡道】【桥梁】【隧道】【折返】【风】【拥堵】【其他】**（【桥梁】【隧道】是【坡道】的细分 subtype，存量库大量使用，保留不改写）。每条尽量带 `distance_km`；确实无法定位的（如"全程侧风"类全段性描述）才允许无公里值。

**`distance_km` 是自由文本**（PR #509 起 `*string`，JSON key 不变），因为难点有"点位"和"路段"两种形态：

- 点位难点（桥、引桥、折返、下穿隧道）：单值，如 `"4.6km"`；
- 路段难点（连续 3-5km 窄路、20-24km 逆风、环湖长侧风段）：起止段，用 en-dash，如 `"10–21km"`，可带地标括注 `"0–10km（外滩→南京西路）"`；
- 描述与 locator 不重复：locator 已写 `"21–35km"` 的，描述里不必再复述同一区间；
- 空白字符串会被后端归一为 null（无定位），别拿空串占位。

## 第 0 步：先有路线串

难点全部锚定在**正确届份**的官方路线串上。没有路线串先跑 marathon-course skill；只有往届路线串时，全部难点结论必须标"往届（XXXX年）参考"。**届份错配是最大坑**：往届数据冒充本届（日期、分项名额对不上即暴露）已在实践中出现多次——拿到任何难点数据先核对届份，再核路线。

## 第 1 步：总爬升

来源按可信度从高到低，取主流值并记区间：

1. 官方高程图/爬升标注（少见，最权威）。
2. 跑者 GPX 实测（运动手表分享、赛记配图）：多源取主流值，记区间（如 25-30m）。
3. 往届参考：**必须标届份**；官方已官宣改线而新线未发布时（如 2026 杭马新增运河段），往届爬升拒收，留待新线发布。

梯度自检：平原赛道约 5-30m（东营 6m / 上马 26m）；丘陵城市 50-150m；山地 200m+（济南 290m）。数值离谱（如平原城市报 200m）先怀疑来源。

## 第 2 步：结构难点（从路线串直接推）

扫描路线串里的：**大桥/引桥/立交/隧道/下穿**（坡道候选）、**折返**（计数+位置）、**江河湖海沿线的长直道**（侧风候选）。逐条核：

- 点名地物（桥/隧/折返/立交）**必须有公里位置**（点位单值或起止段）——这是验收标准，用户人工抽检第一个抓住的就是"说了桥没说在几公里"。连续窄路/长侧风这类段状难点用起止段表示，别硬折成一个中点数字。
- 公里定位方法，按精度选：
  0. **两步路/手表导出的 KML/GPX 轨迹**（若手头有）：精度最高。注意**坐标系坑**——此类文件多为 WGS-84，高德 API 是 GCJ-02（上海偏移约 440m），直接逆地理编码会整体错位一格路（上马案例：淮海中路被标成长乐路、龙腾大道被标成龙吴路，一度误判"轨迹不是官方线"）。转换用高德官方 API `GET /v3/assistant/coordinate/convert?coordsys=gps`（40 点/批），别手抄 GCJ 公式（实测两翻车）。轨迹原始总长与 42.195/21.0975 的比值即校准系数，自带官方 km 刻度标记的先做 ±0.2km 自检；
  1. 官方公里标注（交管通告/路线图带"XXkm 处"）最好；
  2. 高德链式测距：geocode 路线串的路口节点，分段累加直线距离+转弯修正，与官方总长（42.195/21.0975）自校准，误差应压到 ±0.5km；
  3. 往届官方公里标注 + 本届官宣的增删段推算（标注推算口径）。
- **否定性结论要证伪**：声称"无大桥"的，把路线串每一段在地图上过一遍再下结论（长江大桥引桥藏在"宝塔桥西街（过长江大桥后逆行）"这种表述里的案例）。汇总类答案漏桥漏隧常见（广马琶洲大桥×2+磨碟沙隧道×2 全漏的案例）。

## 第 3 步：拥堵堵点（口碑检查）

**查什么**：跑者实际体验中的堵点——起点收窄/首转弯瓶颈、宽路→窄路骤缩、老城窄路单行道、折返并流、上下桥并道、分枪汇流、补给站排队。

**去哪查**（按可检索性）：

1. 赛后吐槽合集/盘点文：搜 `{比赛名} 赛道 吐槽`、`{比赛名} 堵点`、`{比赛名} 赛记 拥堵`、`{比赛名} 起点 收窄`。
2. 知乎/爱燃烧赛记：`site:zhihu.com {比赛名} 赛记`、`iranshao {比赛名}`。小红书内容搜索引擎基本不收录，别浪费时间，能引到二手盘点就引二手并注明。
3. 官方缓堵调整公告：组委会路线调整常带"缓解拥堵"动机（如上马 2020 首转弯由金陵东路改新开河路），搜 `{比赛名} 路线 优化 拥堵`。**查到口碑的同时必查官方调整背景**，两者并存才不误导——路比老路宽 ≠ 不堵。

**验证规则**（一条口碑才能入库）：

1. 堵点必须落在**本届官方路线串**上——抱怨的路不在路线串里 = 届份错了或赛事搞错，拒收。
2. 公里位置用第 2 步方法测；跑友口径的公里数（"0.8km 处"）与链式测距不一致时，以测距为准、口碑口径记入描述。连续窄路段（如 3-5km 老城窄路）用起止段表示，范围两端都要落在路线串上。
3. 记录口径来源：`（跑友口碑+链式测距）`、`（官方调整公告+口碑）`等。
4. 区分"结构性拥堵"（路幅收窄，年年如此，可入库）与"组织性拥堵"（某届拱门摆放失误、某年补给崩了，不入库赛道难点）。

## 第 4 步：自检与拒收纪律

- 每个点名地物有公里值（点位或起止段），或明确说明为何没有（全段性描述）。
- 总爬升过了梯度自检；爬升区间与坡道条目不矛盾（爬升 6m 却列三条大坡 = 有一个错）。
- 届份标注齐全：本届口径 / 往届（XXXX 年）参考，不混写。
- 汇总类（一次问多场）的第三方答案错误率高——单场可用、汇总必逐条复核。
- 官方改线未发布 → 往届数据拒收留档，注明"待新线发布后重查"。
- **不编造**：查不到就写"未查到口碑/无数据"，宁缺毋错。

## 输出格式

```text
【全程】总爬升约 26m（区间 25-30m；跑者 GPX 主流值；2025 届路线参考，2026 起终点官宣不变）

- 【坡道】（无 km，全段微小起伏）城市路面几乎无长上坡（2025 届参考口径）
- 【拥堵】0.8–1.1km 起点外滩金牛广场大道（宽幅）右转新开河路收窄，起跑段排队；跑友口径约 0.8km 处开始挤压、链式测距转弯口 1.0-1.1km。注：该转弯系 2020 年由金陵东路改入以缓解拥堵（官方口径"转弯道更加宽敞"），但相对外滩大道仍收窄、3 万人规模下仍为年年吐槽的堵点（口径：跑友口碑+官方调整公告）
- 【风】21–35km 龙腾大道黄浦滨江开阔段，侧风/逆风为主要变量（GPX 参考）
```
